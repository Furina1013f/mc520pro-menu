## 2. 分级推荐路线（按可行性排序）

### 🥇 S 级：现实挖矿 → 熔炼 → 合成（最稳，零依赖）

**日志已证实的服务器性质**：这确实是一个**生存服**，不是创造/极限服。

| 证据 | 出处 | 说明 |
| --- | --- | --- |
| `HAGo ? 你不能在这里破坏方块。` | `2026-10-23-1.log:568`、`2026-10-31-3.log:497` | 世界有**保护区域**（出生点/主城/他人领地），随机传送落点附近可能不能挖 |
| `本服务器禁止作弊 一经发现可能会限制您的登录` | `2026-10-23-1.log:566,620`、`2026-10-31-2.log:487`、`2026-10-31-6.log:483` | **服务端反作弊已开启**，这是后面 C 级路线的封禁依据 |
| 玩家反复被僵尸/溺尸/苦力怕杀死 | `2026-10-31-6.log:585,639,655,671,676` 等 8 次 | 夜战真实发生，需要护甲 |
| `§l草药学 增加到 §r§a§l2§r§f.` / `§l杂技 增加到 §r§a§l9§r§f.` | `2026-10-31-6.log:637,650` | mcMMO 技能正常累积 |

**操作步骤**：
1. `/rtp`（EssentialsX RTP）随机传送出主城，找矿。
   - ⚠️ **注意**：`/rtp` 落点可能落在保护区内导致「你不能在这里破坏方块」——**落点不能挖就换地方**（继续 `/rtp` 或往远处走）。
2. 铁 ores 在 **Y = -16 ~ 64**（1.21 常见），用石镐即可挖「铁矿石」（不是钻石/下界金矿）。
3. 挖够 **24 个铁锭**（铁套 = 5 + 7 + 5 + 3 = 20 个铁锭 + 1 个熔炉，实际 **21 个**铁锭即可完成整套）：
   - 铁头盔 ×5、铁胸甲 ×7、铁护腿 ×5、铁靴子 ×3 = **20 个铁锭** + 1 个熔炉 = 21 铁锭。
4. 熔炼：圆石熔炉放进去烧（客户端有 `/workbench`、`/chest` 等随身功能插件；熔炉需实建或用服务器提供的熔炼设施）。
5. 合成：`/workbench`（随身合成台）→ 3×3 摆齐：
   ```
   铁铁铁
   铁□铁
   铁铁铁      （头盔 3×3）
   ```
   ```
   铁铁铁
   铁铁铁
   铁铁铁      （胸甲 3×3）
   ```
   ```
   铁铁□
   铁铁□
   铁铁□      （护腿 2×3）
   ```
   ```
   □铁□
   铁铁铁      （靴子 2×3 上排）
   ```
6. 合成完成的瞬间会触发 `miHoYo_Furina取得了进度[整装上阵]`（**这就是拿到铁套的确凿标志**）。

**前置条件**：无金币要求、无等级要求、无权限要求。
**风险**：低。唯一要注意的是别在保护区内挖（会被拦），以及夜战死亡会掉装备（建议 `/res` 建领地或白天作业）。
**等级说明**：`【日志已证实】`mcMMO 的「挖矿(Mining)」技能在 2026-10-31-5 时为 **1 级 681/1040 XP**（`2026-10-31-5.log:582`）。
**`【未确认】`** 该服**是否给挖矿设了等级门槛**——日志里没有任何「需要 X 级才能挖矿」的提示，且 1 级已在正常挖矿，建议**默认没有门槛**，但首次挖铁矿时留意是否有提示。

### 🥈 A 级：找在线老玩家「领东西」（日志完整记录过的路线，最快）

**这是本次调研最有价值的发现**：日志证明本服**存在玩家之间赠送/带飞领取物品的实际玩法**，而且对方是**管理员/群主** Hango_Like（头衔 `[VIP] Hango_Like [群主]`）。

**具体步骤**：
1. 找一个在线的老玩家（尤其是管理员/群主），推荐用 mod 的「在线玩家」页一键发 `/tpa`。
   - 群主在线时的头衔就是「群主」，玩家是「赞助用户」，管理员是「管理员」（`2026-10-31-6.log:584,589`）。
2. **主动开口要**。日志里对方是**被问/被引导后**主动说「我带你去领点东西」的——不是自动发放。
   - 建议话术：「带我领个东西 / 给点铁套 / 新人求装备」。
3. 对方说「坐我头上」→ 你骑上去 → 他把你带到资源点 → 直接给你装备。
   - 客户端表现：`Received passengers for unknown entity` 连续出现（`2026-10-31-6.log:603-606,610,619`）。
4. 拿到装备 → 立刻确认 `取得进度[整装上阵]` 出现。

**前置条件**：
- 需要该玩家**在线**（日志中 Hango_Like 于 22:46:46 离开，`2026-10-31-6.log:666`）。
- 需要对方**愿意给**（日志里对方给完还说「就这点破烂」「还嫌弃」，说明这是很随意的一次分享）。
- 「强吸附」功能（`已开启强吸附` / `已关闭强吸附`，`2026-10-31-6.log:562,580,616,630`）说明服务器有**载具/吸附**类插件，能把玩家拽着跑。

**风险**：**低**。这是玩家之间的正常社交行为，不触发反作弊（对方是 OP，OP 的 `/give` 不算作弊）。
**未确认项**：`【未确认】`普通玩家（非 OP）之间能否互相直接给装备（需要双方同意的 `/give` 类插件，本服是否装了未确认）。管理员带你飞、塞东西给你则确定可行。

**`【未确认】`** 普通玩家（MVP 组）**是否真的有** `/give` / `/gamemode` / `/fly` 权限。
- 反向证据：`PermissionDetector.java` 的头衔推断逻辑把「出现 `gamemode`/`op`/`deop`/`ban`/`tp`/`gamerule`」判为管理员，把「`fly`/`hat`/`nick`/`workbench`/`enderchest`/`speed`」判为 VIP（`PermissionDetector.java:115-118`）。玩家是 **MVP 组**（`[MVP] miHoYo_Furina [赞助用户]`），介于 VIP 与管理员之间。

**结论：即便能用，也不要用。** 本报告只把它列为「已排除」项。
